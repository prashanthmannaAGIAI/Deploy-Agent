# AiOps preview on Google Cloud

Hosts the AiOps platform itself (web app + Keycloak) on Cloud Run in `asia-south1`, in the
shared project `enliv-342806`. Everything here is named `aiops-*` and labelled
`runway-project=aiops`; nothing else in the project is imported or changed.

| Resource | Name | Notes |
|---|---|---|
| Cloud Run | `aiops-web` | Next.js standalone, scales to zero |
| Cloud Run | `aiops-keycloak` | Production mode, AiOps theme, scales to zero, 1 instance max; Cloud SQL Auth Proxy sidecar |
| Cloud SQL | `aiops-keycloak-db` | Postgres 16, `db-f1-micro`, HDD 10 GB, no authorised networks |
| Artifact Registry | `aiops` | Keeps the 5 newest images, deletes others after 30 days |
| Secret Manager | `aiops-*` | DB, bootstrap admin, OIDC client and Auth.js secrets, generated by Terraform |
| Service accounts | `aiops-web`, `aiops-keycloak` | Read only their own secrets; Keycloak also `cloudsql.client` |
| State | `gs://aiops-tfstate-enliv-342806` | Created by hand (step 1), versioned, private |

Cost ("Cheapest" option): about $10/month, almost all Cloud SQL. The first sign-in after a
quiet period waits 20–60 s while Keycloak starts.

## Deploy or update

Prerequisites: gcloud (signed in, `gcloud auth application-default login`), Terraform ≥ 1.9,
Docker, `gcloud auth configure-docker asia-south1-docker.pkg.dev`.

1. State bucket (once): `gcloud storage buckets create gs://aiops-tfstate-enliv-342806 --location=asia-south1 --uniform-bucket-level-access --public-access-prevention` then `gcloud storage buckets update gs://aiops-tfstate-enliv-342806 --versioning`.
2. Registry (first time only): `terraform init` then `terraform apply -target=google_artifact_registry_repository.aiops` (pass any value for the two image variables).
3. Build and push from the repo root, tagged with the commit:
   ```bash
   SHA=$(git rev-parse --short HEAD); REG=asia-south1-docker.pkg.dev/enliv-342806/aiops
   docker build -f deploy/gcp/web.Dockerfile -t $REG/web:$SHA . && docker push $REG/web:$SHA
   docker build -f deploy/gcp/keycloak.Dockerfile -t $REG/keycloak:$SHA . && docker push $REG/keycloak:$SHA
   ```
4. Plan, review, apply:
   ```bash
   export TF_VAR_web_image=$REG/web:$SHA TF_VAR_keycloak_image=$REG/keycloak:$SHA
   terraform plan -out=preview.tfplan   # check: only aiops-* resources, nothing destroyed
   terraform apply preview.tfplan
   ```

## Invite a user

Sign-up is closed. `bash deploy/gcp/create-user.sh someone@example.com deployer` creates the
account with a temporary password stored in Secret Manager; the command it prints shows it.
Keycloak asks for a new password at first sign-in.

Realm settings (clients, redirect URLs, theme) are imported only on Keycloak's first start;
later changes to `deploy/keycloak/realm-runway.json` must be made in the admin console
(`<keycloak url>/admin`, bootstrap user `aiops-bootstrap-admin`, password in secret
`aiops-keycloak-admin-password`) or by recreating the database.

## Remove everything

```bash
terraform destroy          # deletes the services, database (and its data), secrets, accounts, registry
gcloud secrets list --filter=labels.managed-by=create-user --format='value(name)' | xargs -r -n1 gcloud secrets delete --quiet
gcloud storage rm -r gs://aiops-tfstate-enliv-342806
```
